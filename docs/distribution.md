# Distribution and installation

Status: qualified release procedure for Linux x64, macOS arm64, and
Windows x64.

The GPL-linked adapter is not part of the MPL VSIX. The main VSIX packaging
rules exclude `native/**`, and automated tests plus release inspection reject
an accidental adapter inclusion. Its `extensionDependencies` entry names the
separately packaged `menaje.dwg-viewer-libredwg` extension. VS Code selects the
published package matching the current platform.

Each GPL companion is staged only after the standalone adapter package passes
its manifest and checksum verification. It carries the executable at
`native/<target>/`, while `source/` carries the exact checksum-pinned LibreDWG
0.14 source and the adapter source and build scripts. Both the companion VSIX
and standalone archive therefore remain source-complete without depending on
a future download.

This is an engineering compliance review, not legal advice. The policy follows
the [MPL 2.0 executable-form source requirement](https://www.mozilla.org/en-US/MPL/2.0/FAQ/),
the [GNU GPL distribution guidance](https://www.gnu.org/licenses/gpl-faq.html),
and GitHub's
[artifact attestation procedure](https://docs.github.com/en/actions/how-tos/secure-your-work/use-artifact-attestations/use-artifact-attestations).

## Reproducible build gates

The `Release packages` workflow is available as a manual dry run and runs
automatically for a `v<version>` tag. It:

1. checks that the repository, main extension, and companion extension
   versions match the tag;
2. builds the VSIX twice, normalizes bounded ZIP timestamp metadata, and
   requires byte-identical output;
3. checks the canonical main VSIX license, notices, source link, GPL exclusion,
   and companion dependency;
4. builds checksum-pinned static adapters on Linux x64, macOS arm64, and
   Windows x64;
5. creates every adapter archive twice and requires byte-identical output;
6. extracts each adapter package, verifies its internal checksums, and runs
   the packaged executable's bounded `doctor` command;
7. stages every GPL companion from the verified source-complete package,
   packages each platform VSIX twice, and inspects its binary, source and
   byte-identical GPL text;
8. generates GitHub build-provenance attestations and a combined
   `SHA256SUMS`;
9. publishes a GitHub release only for a matching version tag.

Marketplace publication is a separate opt-in switch on a manual workflow run.
It requires dispatching the matching `v<version>` tag and a `VSCE_PAT` secret.
The workflow publishes all three GPL platform companions first and the MPL
viewer last, as prereleases. A normal tag push or manual dry run does not
publish to the Marketplace.

GitHub artifact attestations provide keyless build provenance for this public
repository. They are not Apple Developer ID signatures or notarization. The
release pipeline uses the open-source components recorded in
[`licensing.md`](licensing.md) and does not rely on a proprietary CAD SDK.

The `Viewer packages` workflow separately normalizes the npm package gzip
timestamp and OS header fields before comparing archives, checks the actual
archive SHA-256 and byte length against
[`compatibility/viewer-core.json`](../compatibility/viewer-core.json), and
then verifies the platform-neutral extracted-content digest. This prevents a
macOS/Linux gzip header difference from being mistaken for a matching
published artifact.

The `Viewer WebGL packages` workflow applies the same immutable-artifact rule
to the embeddable renderer and DWG Scene Cache source. It reads the version
from `packages/webview/package.json`, requires the Scene Cache package to use
the same version, derives the only accepted release tag as
`viewer-webgl-v<version>`, and checks the normalized archives against
[`compatibility/viewer-webgl.json`](../compatibility/viewer-webgl.json).
Consumers therefore do not have to repeat or infer a version from the product,
Viewer Core, protocol, or Host message versions. The WebGL package train is
independent of the DWG Viewer application and Viewer Core package trains.

To reproduce the VSIX locally:

```bash
pnpm install --frozen-lockfile
pnpm --dir apps/vscode-extension run build
pnpm --dir apps/vscode-extension exec vsce package \
  --no-dependencies \
  --out /absolute/new/path/dwg-viewer-vscode-0.1.2.vsix
```

To reproduce an adapter package, use the checksum-pinned preparation and
deterministic packager described in
[`adapters/libredwg/README.md`](../adapters/libredwg/README.md).

After extracting that verified package, reproduce its companion VSIX with:

```bash
pnpm --dir apps/vscode-libredwg-adapter run prepare:package -- \
  --package-root /absolute/path/dwg-viewer-libredwg-0.14-darwin-arm64 \
  --target darwin-arm64
pnpm --dir apps/vscode-libredwg-adapter exec vsce package \
  --target darwin-arm64 \
  --no-dependencies \
  --out /absolute/new/path/dwg-viewer-libredwg-0.1.2-darwin-arm64.vsix
```

## Verify a downloaded release

Place the main VSIX, all three companion VSIX files, all three adapter archives,
and `SHA256SUMS` in one directory.
On Linux:

```bash
sha256sum -c SHA256SUMS
```

On macOS:

```bash
shasum -a 256 -c SHA256SUMS
```

With GitHub CLI, verify provenance for the artifact you intend to install:

```bash
gh attestation verify dwg-viewer-vscode-0.1.2.vsix \
  --repo menaje/dwg-viewer
gh attestation verify dwg-viewer-libredwg-0.1.2-darwin-arm64.vsix \
  --repo menaje/dwg-viewer
gh attestation verify dwg-viewer-libredwg-0.14-darwin-arm64.tar.gz \
  --repo menaje/dwg-viewer
```

Use the matching Linux companion and adapter filenames on Linux, and the
`win32-x64` filenames on Windows.

## Install

From the VS Code Marketplace, install **DWG Viewer**. Its declared dependency
causes VS Code to install **DWG Viewer — LibreDWG Engine** for the current
platform. The companion must already be published for every supported target.

For a manual or offline installation, install the matching GPL companion first
and then the MPL viewer:

```bash
code --install-extension dwg-viewer-libredwg-0.1.2-darwin-arm64.vsix
code --install-extension dwg-viewer-vscode-0.1.2.vsix
```

The viewer finds the companion executable automatically and runs its bounded
self-test before conversion. No path selection is needed. The standalone
adapter archive remains available for controlled deployments; extract it into
a directory controlled by the current user, run its self-test, and select it
only when deliberately overriding the companion:

```bash
tar -xzf dwg-viewer-libredwg-0.14-darwin-arm64.tar.gz
cd dwg-viewer-libredwg-0.14-darwin-arm64
bin/libredwg-adapter doctor
```

On Linux, use the `linux-x64` archive and extracted directory name. On
Windows, use the `win32-x64` archive and run
`bin\libredwg-adapter.exe doctor` before selecting
`bin\libredwg-adapter.exe`. In VS Code, run
**DWG Viewer: LibreDWG 변환기 선택** and choose the platform executable. The
extension repeats the same self-test before saving the path.

The macOS package is not notarized with an Apple Developer ID. If macOS
blocks a verified download, use the operating system's normal
Privacy & Security approval flow for that specific binary. Do not disable
Gatekeeper globally.

## Publication checklist

- All CI and adapter qualification jobs pass on the intended commit.
- Repository and extension versions are identical.
- Main and companion extension versions are identical.
- The release tag is exactly `v<version>`.
- Manual `Release packages` dry run succeeds before creating the tag.
- Main VSIX, all three companion VSIX files, and all three adapter archives
  have valid GitHub attestations.
- `SHA256SUMS` verifies all release files.
- Release notes identify the MPL VSIX and GPL adapters as separate artifacts.
- Marketplace publication, when explicitly requested, publishes every GPL
  platform companion before the dependent MPL viewer.
- The packaged MPL text matches the official canonical text and project
  copyright remains in `NOTICE`.
- The Webview production dependency audit matches the copyright and permission
  notices included in `THIRD_PARTY_NOTICES.md`.
- The Windows native-path and VS Code display-scale qualification artifacts
  pass on the intended commit.

For the embeddable WebGL packages, use the separate
`viewer-webgl-v<version>` tag. The package manifest is the authoritative
version source; the workflow rejects a manually mistyped tag, mismatched Scene
Cache version, unapproved compatibility manifest, or archive digest mismatch.
